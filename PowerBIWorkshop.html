Power BI 人資儀表板工作坊

Part 1 · 資料清理：員工基本資料

難度：入門 預估 50–60 分鐘 工具：Power BI Desktop 主題：資料清理

目的

真實的人資資料通常很雜亂：性別欄中英文混雜、台灣用民國年、有空白列、也有重複的人。本單元從介面導覽開始，接著把員工基本資料從清理、修正日期、縱向合併，一路做到新增年齡與年資的計算欄位。

學習目標

完成本單元後，應能夠：

  • 說出 Power BI 三大檢視（報表、資料、模型）各自的用途。
  • 把 Excel 多工作表資料匯入 Power Query，並讀懂查詢設定中的套用步驟。
  • 判斷常見的資料品質問題，並用移除空白列、移除重複、欄位篩選清到 100% 有效。
  • 把民國年轉成西元年，讓三張表欄位對齊後縱向合併成一張。
  • 用取代值統一欄位寫法，並新增年齡、年資與分組區間欄位。

開始之前：怎麼開啟 Power Query

Power Query 是 Power BI 內建的資料清理工具，所有清理動作都在它的獨立編輯器視窗完成。有兩個入口，依手邊有沒有資料而定。

入口 A還沒匯入資料時
  1. 在 常用 功能區點 取得資料 › 選來源（例如 從 Excel 活頁簿）。
  2. 在導覽視窗勾選要的工作表後，按 轉換資料，就會開啟 Power Query 編輯器。
入口 B資料已經載入時
  1. 直接在 常用 功能區點 轉換資料。
  2. 同樣會開啟 Power Query 編輯器，可以繼續調整既有的查詢。

兩個關鍵動作

要清資料一律走轉換資料，不要按載入（載入會跳過清理直接把資料丟進報表）。在編輯器裡改完後，左上角按 關閉並套用 就會回到 Power BI 主畫面。

打開 Power BI Desktop，看畫面最左邊那一排三個圖示，由上而下分別是會反覆切換的三個檢視。

報表檢視實際擺放圖表、做視覺化。建立視覺化與儀表板時會大量用到。

模型檢視當有多張表時，在這裡拉關聯、定義表與表之間的關係。

2暖身：這份資料有什麼問題？

先別急著匯入。打開 01_Employee_Data 這個 Excel，花兩分鐘觀察台灣這張表，想一個問題：如果待會要拿這份資料做分析，可能會卡在哪裡？

這份檔案實際藏了這些狀況，對照看看能找到幾個：

問題在這份資料裡長這樣
格式不一致性別欄同時出現 Male、Female、男性、女性，四種寫法混在一起。
不同源台灣的出生日期是民國年（例如 72/04/05），日本與美國是西元年。
空值有人有員工編號，但姓名欄是空的（例如 EMP081）。
重複資料同一筆資料被輸入了不只一次（例如 EMP064 出現兩次）。
整列空白美國表裡夾了一整列完全沒填的空白列。

延伸：其他常見的資料毛病

除了上面這些，真實場景還常遇到兩種。一是遺漏值：例如某個國家應該交回的資料筆數對不上，少了一塊。二是複合資料：一個欄位塞了一種以上的資訊，最常見的是地址（高雄市 + 三民區 + 街道全擠在一格），但實際上只想要城市。複合資料通常要用拆分欄位處理，屬於後續單元的進階主題。

為什麼要先看資料

發問卷或收名單時，資料很難完全乾淨，紙本回收尤其明顯。匯入前先檢查原始資料，能省下後面大量除錯的時間。資料格式不對，計算行為就會跟著錯：日期若被當成文字，就算不出兩個日期差幾天。

3把資料匯進 Power Query

本單元只處理員工基本資料這個檔案；離職資料與滿意度調查於後續單元使用。

步驟 2-1從 Excel 取得資料
  1. 在常用功能區點 取得資料 › 從 Excel 活頁簿。
  2. 找到剛剛下載的 01_Employee_Data 檔案，開啟。
步驟 2-2三張表全部勾選
  1. 導覽視窗會出現三個工作表：Taiwan、Japan、US。
  2. 三個都打勾。
  3. 下方有兩個按鈕，不要按載入，請按 轉換資料。

別按錯按鈕

這裡要按轉換資料，不是載入。轉換資料會進入 Power Query 編輯器去清理；直接載入則會把髒資料原封不動丟進報表。這一步錯了，後面整段都會跟著歪。

4認識 Power Query 編輯器

轉換資料之後會進到一個新視窗，這就是 Power Query 編輯器。先別動手，花一分鐘認識三個區塊。

區塊位置作用
查詢窗格最左邊列出目前載入的所有表，這裡會看到 Taiwan、Japan、US 三張。點不同的表就切換，類似 Excel 切換工作表。
資料預覽中間顯示目前選到那張表的內容。點欄位標題可以選取整欄。
查詢設定最右邊下方的套用步驟會記錄做過的每一個動作，可回放、可刪除、可修改。
公式列預覽區上方顯示每個步驟的 M 語言公式，可直接編輯。

讀懂套用步驟

先點查詢窗格裡的 Japan，看右邊套用步驟，預設通常會有四步。它們是 Power BI 自動產生的，理解它在做什麼很重要：

步驟發生了什麼事
來源 Source讀取資料來源。點旁邊的齒輪設定圖示，會看到檔案路徑。改這裡的來源，後面所有步驟會自動套用到新檔案，這就是資料能無痛更新的原因。看完記得取消，不要改。
導覽 Navigation從活頁簿裡定位到所選的那張工作表。
已將標頭升階原本第一列被當成一般資料，這步把第一列升級成欄位名稱。
已變更類型讀進來時每欄是未定型（欄位標題顯示 ABC123）。這步自動偵測並分流成正確類型，例如日期欄會出現日曆圖示。

看一個小細節

點欄位標題左邊的小圖示：ABC 代表文字、123 代表數字、日曆代表日期。類型對不對，直接影響後面能不能做運算。這是判斷資料健康的第一個快速指標。

5動手清理：空白列與重複

以下是真正的實作。先點 Taiwan 這張表，跟著做。先打開一個幫手，再清掉空白列與重複資料。

步驟 4-1打開資料行品質
  1. 點上方的 檢視表 功能區。
  2. 把 資料行品質 打勾。
  3. 每個欄位標題下方會出現一條綠色品質列，顯示這一欄有多少是有效、錯誤、空白。沒填滿、有黑色或缺口的，代表這欄有問題。

目標很單純：把每一欄的綠色品質列清到 100% 有效。

步驟 4-2移除空白列
  1. 回到 常用 功能區。
  2. 點 縮減資料列 › 移除資料列 › 移除空白資料列。
步驟 4-3移除重複項目
  1. 同樣在 縮減資料列 › 移除資料列 › 移除重複項目。
  2. 這會把整列完全一樣的重複資料清掉。

移除空白列清不掉「半空白」

移除空白資料列只認整列都是空的情況。但台灣表裡的 EMP081 有員工編號、只有姓名是空的，它不算整列空白，所以還會留著。這種半空白要靠下一步的欄位篩選處理。

測試帳號

除了空白與重複，實務上也常有測試帳號，例如姓名是 test、或明顯非真實員工的列。發現時在這個階段一併用篩選或移除列刪掉。本範例資料沒有測試帳號，但收回來的真實資料經常會有。

步驟 4-4用篩選清掉姓名為 null 的列
  1. 在 姓名 欄位標題右邊，點那個向下的篩選箭頭。
  2. 把清單裡的 (null) 取消勾選，確定。
  3. 回頭看品質列，姓名欄現在應該是 100% 有效。

Checkpoint

停下來看台灣表的每一欄品質列。全部都顯示 100% 有效，沒有空白或錯誤，這張表就過關了。台灣表清完應該是 80 筆左右。

6三張表都要做一次

同樣的三個動作，請在 Japan 和 US 各做一遍，三張表都要確認完成。

移除空白資料列 移除重複項目 必要時用篩選清掉 null

小提醒

有編號但姓名空白的半空白情況只出現在台灣表，所以只有台灣需要多做步驟 4-4 的姓名篩選。日本和美國用移除空白列加移除重複項目就夠了。不管哪張表，最後都用品質列逐欄確認到 100%。

Checkpoint

三張表的所有欄位品質列都是 100% 有效，才算完成本節。

7把民國年轉成西元年

台灣的出生日期是民國年（例如 72/04/05）。Power BI 會把 72 誤判成西元 1972，所以要先拆掉錯誤的偵測，再自己換算。

步驟 1-1刪除自動的變更類型步驟
  1. 點 Taiwan 表，在右邊查詢設定找到第四個套用步驟 已變更類型。
  2. 把這個步驟刪除。如果跳出會影響後續步驟的提示，選擇刪除即可。
  3. 回到最新步驟，出生日期會恢復成原本的民國年文字。
步驟 1-2新增自訂資料行做換算
  1. 上方點 新增資料行 › 自訂資料行。
  2. 欄位名稱填 BirthDate_西元。
  3. 打開練習檔的語法表，找到民國轉西元那一項，複製整段 M 公式文字，貼進公式框：
Power Query · MDate.FromText( Text.From(Number.From(Text.BeforeDelimiter([BirthDate],"/"))+1911) &"/"& Text.AfterDelimiter([BirthDate],"/",0) )
這段公式在做什麼（逐行說明）

以 72/04/05 為例，由內往外讀：

Text.BeforeDelimiter([BirthDate],"/") 取第一個斜線前的文字，得到 72。

Number.From(...) 把文字 72 轉成數字。

+1911 是民國轉西元的核心：西元等於民國加 1911，所以 72＋1911＝1983。

Text.From(...) 把 1983 轉回文字，再用 &"/"& 跟後半段接起來。

Text.AfterDelimiter([BirthDate],"/",0) 取第一個斜線之後的文字，得到 04/05。

組合後是文字 1983/04/05，最外層的 Date.FromText(...) 再把這串文字變成真正的日期值。

  1. 確定後，最右邊會長出一欄 BirthDate_西元。

只貼文字，不要連欄位一起貼

從語法表複製時，只複製公式文字本身。如果把欄位名稱或格式一起貼進去，公式會跑掉、甚至多冒出幾欄。貼完看公式框下方，要顯示綠色勾與未偵測到任何語法錯誤，才按確定。連同後面的右括號都要貼齊。

Checkpoint

看第一位員工：原本是民國 72 年，換算後 BirthDate_西元 應顯示 1983/04/05。對得起來就成功了。

8整理欄位與步驟名稱

換算好之後，把舊欄位清掉、欄位順序對齊其他表，並幫步驟取名字。

步驟 2-1移除原本的民國生日欄
  1. 在原本的 BirthDate 欄位標題上按右鍵 › 移除。
步驟 2-2讓三張表的日期欄同名又同型別
  1. 把新欄 BirthDate_西元 重新命名回 BirthDate。附加查詢是依欄位名稱對齊（不是依順序），這樣台灣的出生日期欄就跟日本、美國同名，另外兩張表完全不用動。
  2. 剛剛刪掉台灣的已變更類型後，台灣整張表的欄位會退回未定型。把台灣的 BirthDate 和 HireDate 都重新設成日期型別。
  3. 確認三張表的 BirthDate 與 HireDate 型別都是日期，合併與後面的計算才不會出錯。

對齊靠名稱，不是順序

常見誤解是以為欄位要排成一樣的順序才能合併。實際上附加查詢是用欄位名稱配對：名稱對得上就會併到同一欄，對不上就會各自長出一欄、其餘補 null。所以重點是同名，順序只是方便閱讀。

步驟 2-3幫步驟重新命名
  1. 在查詢設定的套用步驟上按右鍵 › 重新命名。
  2. 把新增自訂的那步改成 民國轉西元，移除欄位那步改成 移除民國生日。

為什麼要命名步驟

套用步驟會完整記下做過的每個動作。預設名稱像已新增自訂看不出用途；改成看得懂的名字，日後回頭維護時，一眼就知道每一步在做什麼。

Checkpoint

確認三張表的出生日期欄都叫 BirthDate、且為日期型別，HireDate 也是日期，欄位名稱都對得起來。

9合併三張表

把台灣、日本、美國併成一張大表。在 Power Query 裡不需要手動剪貼，用附加查詢就行。

步驟 3-1附加為新查詢
  1. 到 常用 功能區，點 附加查詢 旁的小箭頭 › 將查詢附加為新查詢。
  2. 選擇三個或以上資料表，把 Taiwan、Japan、US 都加進來，確定。
  3. 會產生一張新表 附加1，把它重新命名為 員工基本資料。

兩種附加的差別

直接用附加查詢會把其他表併進台灣這張原表、改動原始查詢。將查詢附加為新查詢則是另外長出一張新表，三張原始表都原封不動保留。這裡選後者。

合併的前提：欄位要對得起來

三張表的欄位數要相同、欄位名稱要一一對應（出生日期欄都叫 BirthDate、姓名對姓名、編號對編號），而且同一欄的資料類型要一致。特別注意日期：BirthDate 與 HireDate 在三張表都要是日期型別。若哪一欄沒被辨識成日期，回去把它改成日期類型，否則合併或後面的年齡、年資計算會出錯。

原始三張表為什麼沒變

新查詢就像長出一張全新的表，後續的值轉換都在這張新表上做，原始三表不會被動到。也因此 Part 1 裡某些清理只在台灣表做，因為其他兩張表沒有那個問題。

11新增年齡與年資

原始檔沒有年齡和年資，要自己算。一樣用新增資料行的自訂資料行，貼上語法表的公式。

步驟 5-1新增年齡欄
  1. 新增資料行 › 自訂資料行，命名 年齡。
  2. 貼上年齡公式，看到綠色勾再確定：
Power Query · MDate.Year(DateTime.LocalNow()) - Date.Year([BirthDate])
這段公式在做什麼（逐行說明）

DateTime.LocalNow() 取現在的日期時間。

Date.Year(...) 從中抽出年份，例如 2026。

Date.Year([BirthDate]) 抽出出生年份，例如 1983。

兩者相減：2026 − 1983 ＝ 43。

注意：這是純年份相減、不看月日。如果今年生日還沒到，算出來會比實際歲數多 1。要精確就得改用完整日期比較，教學用這個近似即可。

概念很單純：用今年的年份直接減掉出生年份，不用真的去數日期。

步驟 5-2新增年資欄
  1. 再新增一個自訂資料行，命名 年資。
  2. 貼上年資公式，確定：
Power Query · MNumber.Round( Duration.Days( Date.From(DateTime.LocalNow()) - [HireDate]) / 365, 1)
這段公式在做什麼（逐行說明）

DateTime.LocalNow() 取現在，Date.From(...) 去掉時間、只留日期。

減掉 [HireDate] 得到一段時間長度（Duration）。

Duration.Days(...) 把這段時間換算成總天數，例如 3450 天。

/ 365 把天數換成年，約 9.45。

Number.Round(..., 1) 四捨五入到小數一位，得 9.5。

注意：除以 365 沒有計入閏年，會有極小誤差，對人資分析的呈現沒有影響。

概念是把到職日到今天的天數除以 365，再四捨五入取小數一位。

公式與語法表一致

步驟 8 已把日期欄改名回 BirthDate，公式直接用 [BirthDate]，與語法表完全一致。若欄位另有命名，中括號裡的名稱要跟著改，否則公式會報錯。

算之前先確認資料類型

所有運算都要靠欄位的資料類型才會正確。公式報錯時，先點欄位標題左邊的類型圖示檢查：日期欄要是日期、數字欄要是數字、文字欄要是文字。這跟在統計軟體裡設定變數是連續或類別是同一個道理，型別設對，運算才對。

聯結種類保留什麼
左方外部（最常用）保留左表全部列，右表有對應就補入，無對應填 null。
右方外部保留右表全部列，左表有對應就補入，無對應填 null。
完整外部左右兩表全部保留，彼此無對應的欄位互相填 null。
內部只保留兩表都有對應的列，任一方無對應就刪除。
左反（Left Anti）只保留左表中、在右表找不到對應的列。
右反（Right Anti）只保留右表中、在左表找不到對應的列。

7建立日期表

時間智慧函數（去年同期、累計等）需要一張完整且連續的日期表才能正確運作，例如算年度離職人數、月增減人數。用空白查詢貼上語法即可生成。

步驟 7-1用空白查詢貼上日期表語法
  1. 常用 › 新來源 › 空白查詢。
  2. 常用 › 進階編輯器，把日期表語法整段全選貼上，取代原本內容：
Power Query · Mlet Today = Date.From(DateTime.LocalNow()), StartDate = #date(2020, 1, 1), EndDate = Date.EndOfYear(Today), #"List of Dates" = List.Dates(StartDate, Duration.Days(EndDate - StartDate) + 1, #duration(1, 0, 0, 0)), #"Converted to Table" = Table.FromList(#"List of Dates", Splitter.SplitByNothing(), type table [Date = Date.Type]), #"Insert Year" = Table.AddColumn(#"Converted to Table", "年", each Date.Year([Date]), Int64.Type), #"Insert Quarter Number" = Table.AddColumn(#"Insert Year", "季度數字", each Date.QuarterOfYear([Date]), Int64.Type), #"Added Quarter" = Table.AddColumn(#"Insert Quarter Number", "季度", each "Q" & Text.From(Date.QuarterOfYear([Date])), type text), #"Add Year-Quarter" = Table.AddColumn(#"Added Quarter", "年-季度", each Text.From(Date.Year([Date])) & "-Q" & Text.From(Date.QuarterOfYear([Date])), type text), #"Insert Month Number" = Table.AddColumn(#"Add Year-Quarter", "月份數字", each Date.Month([Date]), Int64.Type), #"Insert Month Name" = Table.AddColumn(#"Insert Month Number", "月份", each Date.MonthName([Date], "TW-zh"), type text), #"Insert Month-Year" = Table.AddColumn(#"Insert Month Name", "年-月份", each Date.ToText([Date], "yyyy MMM"), type text), #"Insert YYYY-MM" = Table.AddColumn(#"Insert Month-Year", "YYYY-MM", each Date.ToText([Date], "yyyy-MM"), type text), #"Rename Column" = Table.RenameColumns(#"Insert YYYY-MM", {{"Date", "日期"}}) in #"Rename Column"
這段語法逐行在做什麼

Today 取現在的日期，當作日期表的結束依據。

StartDate = #date(2020, 1, 1) 把日期表從 2020 年元旦起算，EndDate 抓到今年年底。

List of Dates 用 List.Dates 從起始日逐日列到結束日，確保中間連續不漏；再轉成資料表。

2認識關聯：種類與篩選方向

建立關聯前，先搞懂兩個概念：兩張表的數量關係（關聯種類），以及篩選從哪邊流向哪邊（篩選方向）。設對了，DAX 才會算對。

關聯種類

種類意義與例子
一對多（1 : N）主表每筆對應子表多筆，一端的鍵欄位需為唯一值。最常見。例：日期表的每一天是唯一值，對到員工或離職資料中同一天的多筆紀錄。
一對一（1 : 1）兩表嚴格一對一，兩邊鍵欄位都唯一。例：一位員工最多一筆離職紀錄，員工基本資料對離職資料。較少見。
多對多（N : N）雙方都可對應多筆，兩邊鍵都不唯一。容易效能不佳、篩選邏輯打架，盡量避免。

篩選方向

方向說明
單向（預設）篩選從一端流向多端。選定某年度，自動篩出該年的對應紀錄。多數情境用單向即可。
雙向篩選可雙向流動。複雜模型容易造成循環錯誤，盡量避免。

1量值語法解剖

DAX（Data Analysis Expressions）是 Power BI 的計算語言，長得像 Excel 函數，但以整欄、整表為單位運算。先用離職率拆解一條量值的結構。

DAX離職率 = DIVIDE( COUNTROWS('離職資料'), [員工人數], 0 )
這條量值的每一段是什麼

離職率 是量值名稱。寫 Excel 公式時無法為公式命名；DAX 每條量值都要先取名字，之後用名字引用。

DIVIDE 是 DAX 函數，全部大寫，這裡做的是安全除法。

COUNTROWS('離職資料') 計算離職資料表的總列數，也就是離職人數。資料表引用用單引號。

[員工人數] 是量值引用：方括號內放量值名稱、不寫資料表名稱，代表引用先前算好的另一條量值。

0 是除零替代值：分母為零時顯示 0，而不是報錯。

與 Excel 公式最大的不同

Excel 的公式是對一格計算、要往下填滿整欄；DAX 一條公式就是對整欄或整表計算，不需要填滿。寫好之後也可以自由換行排版，Power BI 不受換行影響，巢狀公式因此能寫得清楚易讀。

2撰寫規則

規則說明
量值名稱自訂、每條公式都要命名，名稱不含空格。
函數名稱全大寫，如 CALCULATE、DIVIDE，輸入時有 IntelliSense 自動補全與參數提示。
欄位引用格式是 '資料表名稱'[資料行名稱]，例如 '員工基本資料'[年資]，輸入單引號即可呼叫清單。
量值引用格式是 [量值名稱]，不寫資料表名稱，輸入左方括號即可呼叫。
括號配對每個函數都有一組括號，巢狀時特別注意對稱，少一個就報錯。先乘除後加減的優先順序也靠括號控制。
換行排版可自由換行增加可讀性，巢狀公式比較好讀，計算不受影響。

3常用函數

函數用途
COUNTROWS(表)計算資料表總列數。COUNTROWS('員工基本資料') 就是員工總人數。
DISTINCTCOUNT(欄)計算欄位不重複值的數量，重複的值會被排除。
AVERAGE(欄) / SUM(欄)平均與加總，用法同 Excel。
CALCULATE(運算式, 篩選…)在指定篩選條件下重新計算，最核心的函數。例如只算在職者、只算某部門。
FILTER(表, 條件)從資料表篩出符合條件的子集。
DIVIDE(分子, 分母, 替代值)安全除法，分母為零回傳替代值不報錯。
SAMEPERIODLASTYEAR(欄)去年同期，等同 DATEADD(欄, -1, YEAR)。搭配日期表自動抓出去年相同區間。

4實作：建立量值

在欄位窗格的資料表上按右鍵就能新增量值，公式從語法表複製。先建最關鍵的在職人數。

步驟 4-1新增在職人數量值
  1. 在欄位窗格對 員工基本資料 按右鍵 › 新增量值。
  2. 輸入 在職人數 =，貼上語法表的公式，確定：
DAX在職人數 = CALCULATE( COUNTROWS('員工基本資料'), USERELATIONSHIP('員工基本資料'[HireDate], '日期表'[日期]), '日期表'[日期] <= MAX('日期表'[日期]), OR( ISBLANK('離職資料'[TerminationDate]), '離職資料'[TerminationDate] > MAX('日期表'[日期]) ) ) + 0
這條公式為什麼這麼複雜

要算某個時間點的在職人數，光看離職欄位不夠，要同時考慮入職日與離職日。例如 2023 年入職、2025 年離職的人，只在 2023 到 2024 算在職，2025 之後就不算。

MAX('日期表'[日期]) 抓出目前篩選區間的最後一天，當作判斷的時間點。

USERELATIONSHIP 指定改用入職日與日期表的關聯來計算。

OR(ISBLANK(...), ... > MAX(...)) 的意思是：沒有離職日、或離職日在時間點之後的人，才算在職。

+ 0 讓沒有資料時顯示 0 而不是空白。

步驟 4-2照語法表把其餘量值全部建立
  1. 同樣的方式逐一新增。建完後欄位窗格會多出一排帶計算機符號的量值。
  2. 建好的量值點選後，可在上方量值工具設定格式：人數類設整數、平均與成長率取小數 1 位、比率類設百分比。
  3. 離職人數、離職人數(去年同期)、平均留任時長建在離職資料表底下較直觀。
類別要建立的量值
人數在職人數、員工人數、員工人數(去年同期)、員工人數成長率
結構平均年資、平均年齡、平均年齡(去年同期)、主管職人數、女性主管職人數、女性主管比、女性主管比(去年同期)

5時間智慧：去年同期與成長率

主管最常問的是：跟去年同期比如何。不用手動切到去年再抄數字，一條公式解決。

DAX員工人數(去年同期) = CALCULATE( [員工人數], SAMEPERIODLASTYEAR('日期表'[日期]) )
DAX員工人數成長率 = DIVIDE( [員工人數] - [員工人數(去年同期)], [員工人數(去年同期)], 0 )
去年同期為什麼抓得到

Part 3 把日期表與員工基本資料建立了關聯。SAMEPERIODLASTYEAR 透過這條關聯，自動偵測目前報表選到的年份或日期區間，回推去年相同區間再計算。

成長率就是（今年 − 去年）÷ 去年，用 DIVIDE 處理分母為零的情況。

要算在職人數或離職人數的去年同期，把公式中間的量值換掉即可，寫法完全相同。

從一群人裡鎖定目標族群，用 CALCULATE 加上條件：

DAX主管職人數 = CALCULATE( [在職人數], '員工基本資料'[IsManager] = "是" )

女性主管職人數、女性主管比都是同樣的寫法再多一層條件，公式都在語法表。

虛線關聯要用 USERELATIONSHIP 啟用

Part 3 那條日期表對離職日期的關聯是非作用中（虛線），平常不會自動聯動。所以像離職人數、平均留任時長這類以離職日期計算的量值，公式裡都會用 USERELATIONSHIP 暫時啟用那條關聯。想深究某條公式，可以把它貼給 AI 請它逐行解釋。

6快速量值：不寫公式的時間智慧

與去年相比、與上月相比這類常見計算，Power BI 已內建好邏輯，用快速量值點選即可產生。

步驟 6-1建立與去年相比的變化 %
  1. 常用功能區 › 快速量值，開啟選取計算的下拉選單。
  2. 往下找到 時間智慧 分類，選 與去年相比的變化。
  3. 基底值放 離職人數（或在職人數），日期放 日期表 的 日期，期間數填 1（相隔一年）。
  4. 按新增，欄位窗格會多出「離職人數與去年相比 %」。

與上月相比同理

要算月增減就選與上月相比的變化。成果檔矩陣裡用的「在職人數 與上月相比 %」就是這樣建出來的。快速量值產生的 DAX 也可以打開來看，是很好的學習素材。

用 AI 產生 DAX

另一條路是把資料結構描述給 ChatGPT 或 Copilot：員工基本資料含入職日期、離職資料含離職日期、已建好日期表，請幫忙寫計算各部門離職率的 DAX。描述得越完整，產出的公式越能直接貼上使用。

7量值 vs 計算資料行

前面在 Power Query 算過年齡，這裡又用 DAX 算指標，差別在哪？兩者都用公式，但計算時機、儲存方式與用途完全不同。

比較項目量值計算資料行
計算時機動態：每次互動、每次點報表都即時重算。靜態：資料載入時算好就固定。
篩選感知會隨篩選器、交叉篩選改變數值。不感知篩選，算出 29 就一直是 29。
儲存方式只存公式，不佔資料表欄位。成為資料表的一欄，佔記憶體與檔案大小。
拖曳位置放在視覺效果的值區域。放在軸、圖例或篩選器。
外觀欄位窗格帶計算機符號。一般欄位，無計算機符號。
用途舉例離職率、平均年資、成長率。年齡、年齡區間、年資區間。

選用原則

大多數的指標計算都用量值。只有要放在軸或篩選器上的類別（例如年齡區間要逐一出現在長條圖的 X 軸）才需要計算資料行，因為量值做不出類別清單。

  2. 確認方向：員工基本資料為一端、滿意度調查為多端（同一位員工有多個年度的填答）。

資料結構

滿意度調查含 EmployeeID、SurveyYear、七個構面（整體滿意度、薪資、主管關係、職涯發展、工作環境、團隊合作、工作生活平衡）各 3 題的 Likert 1–5 分，加上 Q8_eNPS（0–10 分）。其中 Q1_Overall_3 是留任意願題，後面用它衍生離職意圖。

2前處理：構面平均與離職意圖

每個構面有三題，要先算出構面平均分數當代表值。這一步在 Power Query 做，不用寫公式。

步驟 2-1構面平均（統計資料功能）
  1. 在 Power Query 點 滿意度調查，按住 Shift 選取 Q1_Overall_1 到 Q1_Overall_3 三欄。
  2. 新增資料行 › 統計資料 › 平均，新欄位點兩下改名 Q1-整體滿意度。
  3. Q2 到 Q7 比照辦理，得到七個構面平均欄。
  4. 再按住 Shift 選取 Q1 到 Q7 七個構面平均欄，同樣 統計資料 › 平均，改名 ALL-整體滿意度平均。
步驟 2-2離職意圖（條件資料行）
  1. 新增資料行 › 條件資料行，依 Q1_Overall_3（留任意願）轉換，完成後 關閉並套用：
條件（Q1_Overall_3）輸出
等於 1高
等於 2高
等於 3中
等於 4低
其他（else）低

3建立滿意度量值

滿意 % 的核心邏輯：Likert 給 4 或 5 分視為滿意，計算滿意作答的占比。先建分母用的總數，再建各構面滿意 %。

DAX總數 = COUNTROWS('滿意度調查')
DAX整體滿意度 滿意% = DIVIDE( SUMX( '滿意度調查', IF('滿意度調查'[Q1_Overall_1] IN {4,5}, 1, 0) + IF('滿意度調查'[Q1_Overall_2] IN {4,5}, 1, 0) + IF('滿意度調查'[Q1_Overall_3] IN {4,5}, 1, 0) ), [總數] * 3 )
這條公式在做什麼

IF(... IN {4,5}, 1, 0) 把每一題轉成滿意記 1、不滿意記 0。

SUMX('滿意度調查', ...) 逐列把三題的滿意數加總起來。

分母是 [總數] * 3：每人答三題，滿意作答數除以總作答數，得到滿意比例。

其餘六個構面把欄位前綴換掉即可（Q2_Salary、Q3_Manager…），公式都在語法表。

DAX員工推薦 反對者% = DIVIDE(SUMX('滿意度調查', IF('滿意度調查'[Q8_eNPS] IN {0,1,2,3,4,5,6}, 1, 0)), [總數]) 員工推薦 推廣者% = DIVIDE(SUMX('滿意度調查', IF('滿意度調查'[Q8_eNPS] IN {9,10}, 1, 0)), [總數]) eNPS = [員工推薦 推廣者%] - [員工推薦 反對者%]
DAX高離職意圖% = DIVIDE( CALCULATE([總數], '滿意度調查'[離職意圖] = "高"), CALCULATE([總數], ALL('滿意度調查'[離職意圖])) )

4滿意度頁的視覺設計

建立新頁面命名滿意度報告。這一頁要回答的議題是：員工最不滿意哪個面向、哪群人需要優先介入。

區塊內容與設定
樣本數 卡片放總數量值，標題樣本數。
滿意度總平均 卡片放 ALL-整體滿意度平均欄位，點欄位旁箭頭把摘要改成平均，小數 2 位。
eNPS 卡片放 eNPS 量值（格式百分比、小數 1 位）；圖說文字的值顏色點 fx 設規則：大於 0 綠色、小於 0 紅色。
各年度滿意比例 矩陣列放 SurveyYear、值依序放七個構面滿意 %（顯示名稱可把「滿意%」刪掉）；儲存格元素開資料橫條、用 fx 調整正值橫條顏色。
高離職意圖 直條圖X 軸年齡區間、Y 軸高離職意圖 %，開資料標籤（位置自動）。

Likert 量表的處理慣例

滿意 % 看給 4 或 5 分的占比；eNPS 用推薦者 % 減批評者 %。分析時的三個常用視角：滿意比例當核心指標、依在職與離職等維度比較不同族群、追蹤各構面滿意比例的年度變化。

5動態交叉分析：欄位參數與 SWITCH

成果檔的滿意程度比較圖可以動態切換分析維度與滿意度指標，背後是兩個技巧：欄位參數讓軸可切換、SWITCH 量值讓指標可切換。

步驟 5-1分析維度（欄位參數）
  1. 模型化 › 新增參數 › 欄位，名稱輸入 分析維度。
  2. 欄位加入 EmploymentStatus、Gender、IsManager、Department、JobCategory、JobLevel（點兩下可改顯示名稱、可拖曳排序）。
  3. 勾選在本頁新增交叉分析篩選器，按建立。
  4. 把篩選器改成 按鈕交叉分析篩選器：開單一選取與強制選取；多按鈕版面配置用格線、磚、2×3；選取狀態的按鈕設深色背景與邊界，整體配淺色底與圓角。
步驟 5-2滿意度指標（輸入資料）
  1. 常用 › 輸入資料：第一欄 選項 輸入七個構面名稱、第二欄 索引 輸入 1 到 7，表名 滿意度項目，載入。
  2. 再建一個按鈕交叉分析篩選器，欄位放選項；點一下分析維度篩選器後用 複製格式 刷到這個篩選器，配色改另一組（版面配置縱向 7 列）。
  3. 排序：點選項欄位，資料行工具 › 依資料行排序 › 索引，篩選器再依遞增排序。
步驟 5-3動態指標量值（SWITCH）
  1. 新增量值，依目前選到的選項回傳對應的滿意 %：
DAX滿意度向度 = SWITCH( SELECTEDVALUE('滿意度項目'[選項]), "整體滿意度", [整體滿意度 滿意%], "薪資福利", [薪資福利 滿意%], "主管關係", [主管關係 滿意%], "職涯發展", [職涯發展 滿意%], "工作環境", [工作環境 滿意%], "團隊合作", [團隊合作 滿意%], "工作生活平衡", [工作生活平衡 滿意%] )
步驟 5-4滿意程度比較圖
  1. 建 群組橫條圖：Y 軸放分析維度（參數）、X 軸放滿意度向度量值，關標題、開資料標籤。
  2. 用編輯互動讓這兩個小篩選器只作用在這張圖，不影響整頁。

小範圍篩選的用法

鎖定單一構面就能問出有意思的問題：例如切到薪資福利、維度選在離職狀態，若離職者的滿意度並不低，代表離職可能與薪資無關，要往其他構面找原因。

6關鍵影響因素（Key Influencers）

哪個因素最影響離職，過去要跑統計模型、寫公式才能回答；這個 AI 視覺用拖欄位就能做到。

步驟 6-1建立關鍵影響因素視覺
  1. 視覺效果窗格選 關鍵影響因素。
  2. 分析欄位放 EmploymentStatus（在職／離職）。
  3. 解釋依據放 Q1 到 Q7 七個構面平均，也可加入年資、年齡、部門等維度讓分析更全面。
步驟 6-2解讀結果
  1. 左側列出最關鍵的因素與影響倍數：例如薪資福利平均分數低 0.58 分時，離職的可能性提高 1.6 倍；工作環境低 0.64 分也是顯著因素。
  2. 點選任一因素，右側顯示分布圖，可比較在職與離職者在該構面的平均分數差異。

寫進報告的句型

薪資滿意度偏低的員工，離職風險比其他人高 60%，建議優先檢視薪資結構。把數字寫成這樣的一句話，讀報告的人才知道要採取什麼行動。

7其他內建 AI 功能

功能用途
異常偵測折線圖自動標記統計上的異常點，不用手動設定閾值，適合監控離職率或人數的突波。
分解樹逐層拆解指標的組成，例如離職人數先拆部門、再拆性別，找出貢獻最大的維度，類似可互動的心智圖。
問與答 Q&A輸入中英文問題，自動生成對應圖表；常用問題可預先設定，讓主管自助查詢。
Copilot 與 Fabric自然語言生成報表、量值與摘要洞見，需 Pro 或 Premium 授權，可申請試用。

前三個功能免費版就能使用，建議課後實際試用。

8報告整合與導覽

三頁做完，最後讓它們像一份報告：篩選同步、頁面可導覽、敘事有層次。

步驟 8-1同步交叉分析篩選器
  1. 檢視 › 同步交叉分析篩選器，選取地區篩選器。
  2. 在右側窗格勾選員工儀表板與離職分析兩頁的同步欄。
  3. 測試：任一頁切換地區，另一頁同步反應。
步驟 8-2頁面導覽按鈕
  1. 插入 › 按鈕 › 頁面導覽，按鈕文字輸入目標頁名（例如滿意度報告）。
  2. 動作的類型選頁面導覽、目的地選滿意度報告；在滿意度頁做一顆返回員工儀表板的按鈕。
  3. 編輯模式按住 Ctrl 點按鈕測試跳頁。
頁面回答的問題
第一頁 人力結構總覽公司整體人力健康狀況：人數、年齡、年資的分布。
第二頁 離職分析哪些部門需要優先關注、離職的趨勢與原因是什麼。
第三頁 滿意度診斷員工最在意什麼、哪個構面與族群最需要介入改善。

三大成果回顧

資料清理能力：用 Power Query 處理空值、格式、重複，縱向與橫向合併資料。資料模型與 DAX：建立多表關聯、撰寫離職率、平均年資、滿意度等量值。儀表板產出：人力結構、離職分析、滿意度三頁互動報告。其中資料清理是最通用的能力，之後處理論文問卷或任何資料整理，這套流程都用得上。
